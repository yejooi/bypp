# Flushlist (bypp) 프로젝트 회고 기록

> 해커톤(BYPP) 출품작. 1인 개발. 2026-09-18 ~ 19 진행, 제출 완료.
> 이 문서는 나중에 기억을 되살리고 자기소개서·면접 답변에 쓰기 위한 기록이다.
> 실제 사용자 수, 후기, 지표는 아직 없다. 수치를 만들어 쓰지 말 것.

배포: https://bypp-hackathon.netlify.app · 저장소: github.com/yejooi/bypp
스택: Next.js(App Router) · React · Tailwind · Supabase(DB/Auth) · Anthropic API(서버 라우트 전용) · Netlify

## 1. 한 줄 요약

장바구니에 잔뜩 담아두고 뭘 살지 못 정하는 사람이, **이번 달 예산 안에서 결정을 끝내도록** 돕는 웹 서비스.
기존 앱이 "너무 많이 산다"를 막는다면, 이 서비스는 **"못 고른다"를 풀어 준다.**

## 2. 왜 만들었나 (문제 정의)

- 여러 쇼핑몰(무신사, 지그재그, 쿠팡, 네이버)의 장바구니에 물건을 쌓아두고, 결국 아무것도 못 정하는 사람이 많다.
- 기존 위시리스트·가계부 앱은 전부 **과소비를 전제**로 "안 사게 막는" 방향이다. 실제 문제는 반대쪽이다.
  - 결정을 무기한 미룸 → 정작 필요했던 걸 못 사서 아쉬움.
  - 즉 문제는 **낭비가 아니라 결정 마비**이고, 결과는 **필요한 걸 못 사는 것**이다.
- 그래서 성공 기준도 다르게 잡았다: 지출 감소가 아니라 **미뤄둔 결정이 정리되는 것.** "사도 됨" 판정도 성공이다.

## 3. 어떤 불편을 어떤 기능으로 풀었나

| 불편 | 구현한 기능 |
|---|---|
| 뭘 사야 할지 순서를 못 정함 | 주머니 → AI 심사대 → 살 물건 가판대로 옮기며 순서 정리. 순서는 끌어다 놓거나 톡 눌러 옮김 |
| 예산이 얼마인지 모름 | 목표 선택 후, 수입·소비·기한을 넣으면 몬테카를로 1,000회로 권장 저축액과 월 예산을 역산. 아는 사람은 직접 입력 |
| 예산을 넘는지 계속 계산해야 함 | 순서대로 금액을 쌓다가 예산을 넘는 물건부터 자동으로 "다음 달 선반"으로 내려감. 예산선 리본으로 경계 표시 |
| 장바구니 물건을 하나씩 옮겨 적기 귀찮음 | 장바구니 스크린샷을 올리면 AI가 상품명·가격·사진을 자동 인식. 링크로도 가능 |
| 고민되는 물건의 우선순위가 안 잡힘 | AI 심사대: 물건별 점수와 이유를 제안. 순위는 코드가 계산, 최종 순서는 사용자가 결정 |
| 정리한 느낌이 없음 | 산 물건은 계산대로, 안 사기로 한 물건은 반품함으로. 둘 다 "정리 완료"로 세고, 5초 안에 되돌리기 가능 |
| 내가 잘하고 있는지 모름 | 하단 바에 절약 진행률과 이번 달 저축액. 예산을 아끼거나 넘긴 만큼 캐릭터가 말해 줌 |
| 혼자 하면 재미없음 | 게임 같은 UI(동물의 숲 스킨), 시그니처 캐릭터 치즈냥이, 이웃 위시리스트 구경 |

## 4. 어떻게 만들었나 (작업 방식)

1. **Claude로 계획 수립**: 왜 만드는지, 주요 기능, 설계 원칙 6개를 `CLAUDE.md`로 문서화. 서로 모순되는 기능과 난잡한 화면을 막는 것이 목적.
   미결정 사항은 GitHub 이슈(#1~#7)로 쪼개 하나씩 결정.
2. **Claude Code로 개발**: 계획을 바탕으로 구현하고, 화면을 보며 피드백을 계속 주고받는 방식으로 수정. 하루 스코프 제외 항목(테스트 코드, i18n 등)도 문서에 미리 못 박음.
3. **Stitch로 UI 디자인**: 게임 같은 UI를 핵심 요소로 보고 디자인에 신경 씀. 이후 디자인 리뷰(impeccable critique)를 두 번 돌려 문제를 점검.
4. **검증을 먼저**: UI보다 불확실한 AI 판정을 먼저 스크립트로 검증(Phase 1). 같은 입력 3회 재현성, 납득 가능성, 가격순과 다른 결과가 나오는지 확인.

## 5. 주요 결정과 이유

- **AI에게 순위를 직접 묻지 않는다.** AI는 항목별 파라미터(만족 지속 개월, 사용 빈도, 장바구니 중복)만 추정하고 순위 계산은 코드가 한다. 순위를 물으면 같은 입력에 결과가 달라져 재현이 안 되기 때문.
- **결정권은 사용자에게 둔다.** 결정을 못 하는 사람의 결정을 AI가 대신하면 문제를 오히려 키운다. AI는 "막혔을 때만" 등장하고 결과는 제안일 뿐, 최종 순서는 사용자가 정한다.
- **LLM 추정 지표를 5개에서 3개로 줄였다.** temperature를 고정할 수 없는 모델이라 필드를 늘리면 흔들림이 커짐. 나머지 2개(가격 변동, 없을 때의 불편)는 규칙 기반으로 처리.
- **"이 중 하나만 고르기"를 뺐다.** 결정을 하나 더 얹는 셈이라서. 대신 결과를 먼저 보여주고 가중치 슬라이더(30~100, 완전 가격순은 제외)로 조정하게 함.
- **사용자 입력은 1~5 단계 + 기본값 3, 선택 입력.** "AI 판단을 굳이 안 따를 것 같다"는 고민에서 나온 결정. 사용자가 직접 준 값이 점수에 반영되어 결과에 내 목소리가 들어가게 함. 다 5점으로 찍는 문제를 막기 위해 3개만 두고 안 건드려도 되게 함.
- **손실·죄책감 프레임을 쓰지 않는다.** "예산 초과" 대신 "다음 달 선반", 붉은 배지·취소선 제거, AI 말투는 잔소리 없는 동료 톤. 점수도 최하위가 0점으로 보이지 않게 30~100으로 펼침.
- **쇼핑몰 장바구니 스크래핑을 포기하고 스크린샷 인식을 택했다.** 로그인·JS 렌더링·봇 차단(쿠팡 403)으로 자동 수집이 막혀서, 사이트와 무관하게 동작하는 방식을 선택. 링크 실패 시엔 수동 입력이 항상 폴백.
- **모바일에서는 드래그를 기본 경로로 두지 않았다.** 폰으로 써 보니 긴 화면을 드래그로 오가기 너무 어려워서, 톡 눌러 옮기기 메뉴를 기본으로 하고 드래그는 추가 동작으로.
- **비주얼 컨셉을 하나로 통일했다.** 딸기 테마를 없애고 동물의 숲 스킨으로 통일. 주머니/심사대/가판대/반품함/계산대를 가게 메타포로 묶고, 나무판·천 패치·박스 테이프·컨베이어 벨트로 각 구역의 성격을 표현.

## 6. 문제와 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| DB 저장 시 RLS 오류 | 정책이 제대로 적용되지 않음 | 정책을 지우고 다시 만드는 마이그레이션으로 정리 |
| "세션 없음" 오류 | 항목 추가와 세션 생성이 동시에 일어나는 경쟁 상태 | 세션 생성을 한 번만 하도록 진행 중인 요청을 공유(`ensureSession`) |
| 로그인할 때마다 목표·예산을 다시 물음 | 목표 없이 만든 "미정" 빈 세션이 최신이라 진짜 세션을 가림 + 첫 화면이 저장값을 무시 | 최근 세션 중 목표와 예산이 있는 것을 우선 선택, 저장값이 있으면 바로 보드로 이동 |
| 판정 결과에 "기본값 사용" 표시 | AI 응답에서 일부 항목이 누락 | 누락된 항목만 다시 요청, 그래도 없으면 기본값으로 채워 화면이 비지 않게 |
| 판정이 느려짐(6~9초) | AI의 "생각" 토큰이 시간을 쓰고 가끔 본문이 비어 재요청까지 발생 | 생각을 끄고 측정 → 4~6초, 빈 응답 없어짐 |
| 판정 설명에 변수명(`usage_frequency`)이 노출 | 프롬프트가 변수명을 그대로 언급 | 프롬프트에서 금지하고, 서버에서도 일상어로 치환하는 안전장치 |
| 스크린샷에 광고·추천 상품까지 등록 | 화면의 모든 상품 카드를 인식 | 체크박스·옵션·수량이 있는 "실제 담은 상품"만 담도록 지시 |
| 스크린샷 사진이 엉뚱하게 잘림 | 모델이 준 비율 좌표가 부정확 | 픽셀 좌표로 받고, 종횡비가 이상한 박스는 버림. 실제 이미지로 직접 API를 여러 번 돌려 확인 |
| 폰에서 흰 화면 | Next 16이 다른 기기의 개발 서버 요청을 차단 | 개발 서버에 같은 와이파이 주소를 허용 |
| 하루 배포 한도(100회) 초과로 배포 불가 | 수정할 때마다 배포함 | Netlify로 이전. 이후엔 로컬로 확인하고 요청할 때만 배포하는 규칙으로 변경 |
| 튜토리얼 이미지가 넘길 때마다 깜빡임 | 장을 넘길 때마다 이미지를 새로 불러옴 | 모든 이미지를 미리 깔고 투명도만 전환, 높이 고정 |
| 새로 가입한 계정에 튜토리얼이 안 뜸 | "봤다" 기록이 브라우저 단위 | 계정 단위로 기록 |
| 이름 툴팁이 패널 가장자리에서 잘림 | 패널의 overflow에 가려짐 | 툴팁을 화면 최상단 레이어로 분리 |
| 누구나 AI API를 호출할 수 있음 | 서버 라우트에 인증이 없었음 | 로그인 토큰 필수 + 사용자별 호출 횟수 제한 |

## 7. 배운 점 (자기소개서·면접 소재)

- **문제 정의가 기능을 결정한다.** "과소비"가 아니라 "결정 마비"로 문제를 다시 정의하니 성공 기준, 문구 톤, 예산 초과 처리 방식까지 바뀌었다.
- **불확실한 것부터 검증한다.** AI 판정이 재현되지 않으면 서비스 전체가 무의미하므로 UI보다 먼저 스크립트로 확인했다. 그리고 AI에게 계산을 맡기지 않고 추정만 맡기는 구조로 설계했다.
- **원칙을 문서로 남기고 그 기준으로 판단한다.** 화면을 고칠 때마다 "이게 원칙과 모순되나"를 확인했다(죄책감 문구, 결정권, 하루 스코프 제한).
- **직접 써 보고 고친다.** 폰으로 써 보니 드래그가 안 돼서 구조를 바꿨고, 실제 장바구니 캡처로 돌려 보니 광고가 섞이는 문제를 찾았다.
- **실패해도 화면이 비지 않게 한다.** AI 응답 누락, 파싱 실패, 컬럼 누락, 링크 차단 모두 폴백을 두었다.
- **비용과 보안을 초기에 챙긴다.** API 키는 서버 라우트 전용으로 두고 로그인·호출 제한을 걸었다. (키가 한 번 화면에 노출되어 교체가 필요했던 것도 기억해 둘 것.)
- **AI와 일하는 방식**: 계획은 함께 세우고, 구현은 피드백을 반복하며 다듬었다. 내가 한 일은 방향과 원칙을 정하고, 화면을 보고 기준을 제시하고, 결과를 검증하는 것.

## 8. 자기소개서용 문장 예시 (다듬어 쓸 것)

- "장바구니에 물건을 쌓아두고 결정을 못 하는 문제를 '과소비'가 아니라 '결정 마비'로 다시 정의하고, 결정을 끝내 주는 서비스를 1인으로 하루 만에 기획·개발·배포했습니다."
- "AI가 순위를 직접 매기면 결과가 흔들리는 것을 확인하고, AI는 추정만 하고 순위는 코드가 계산하는 구조로 설계해 재현성을 확보했습니다."
- "폰으로 직접 써 보니 긴 화면에서 드래그가 어려워, 톡 눌러 옮기는 메뉴를 기본 경로로 바꿨습니다."
- "쇼핑몰 자동 수집이 막혀 있음을 확인하고, 스크린샷 인식으로 우회하되 광고 상품 제외와 사진 좌표 보정까지 실제 이미지로 반복 검증했습니다."
- "배포 한도 초과로 배포가 막히는 문제를 겪고, 매번 배포하던 방식을 로컬 검증 후 배포로 바꾸고 다른 호스팅으로 이전해 해결했습니다."

## 9. 남은 것 / 다음에 할 일

- 서비스명 최종 확정(Flushlist / Unstuck 후보, 이슈 #2). 현재 화면에는 Flushlist를 사용.
- 실제 사용자 피드백 수집. 아직 지표가 없으므로 자기소개서에는 "검증한 것"과 "검증할 것"을 구분해서 쓴다.
- 이웃 화면에서 가격은 화면에서만 숨겨져 있음(DB 정책은 아직 공개 읽기). 완전히 숨기려면 서버 쪽 정책 필요.
- Anthropic 키 교체와 지출 한도 설정(대화 화면에 키가 한 번 노출됨).
- 판정 점수 저장(새로고침하면 사라짐), 판정 후 상태의 DB 반영.
